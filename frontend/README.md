# докчек — фронтенд-прототип

Интерфейс сервиса проверки проектной документации на React, TypeScript и Vite. Закрывает первую задачу Валерия и следующий шаг из «Первых задач команды»: выбор одного файла и показ списка замечаний на демонстрационных данных.

## Что реализовано

- Выбор одного файла кнопкой или перетаскиванием; имя, размер, замена и удаление выбранного файла. Перетаскивание нескольких файлов показывает понятную ошибку.
- Кнопка «Проверить» недоступна без файла. После выбора она открывает явно обозначенный пример отчёта; пример также можно открыть без файла.
- Пять синтетических замечаний с категорией, местом, проблемой, пояснением правила и рекомендацией. Выбор замечания открывает подробности; его текст можно скопировать.
- Четыре сценария демо: замечания, отсутствие замечаний, частичный результат и ошибка с повторной попыткой. Новый документ возвращает к выбору файла.
- Адаптивная вёрстка, управление с клавиатуры, видимый фокус и объявления статусов для вспомогательных технологий.

Содержимое файлов не читается и не анализируется. Нет загрузки на сервер, API, авторизации или хранения документов. Используются только локальные метаданные выбранного файла. Форматы и размер для рабочего сервиса ещё не согласованы, поэтому прототип не вводит вымышленных ограничений.

Правила и замечания — примеры для демонстрации интерфейса, а не утверждённый стандарт компании. Результат не зависит от содержимого выбранного файла.

Визуальное направление вдохновлено [Serro](https://serro.ai/) и его [публичным скриншотом](https://www.goatedui.dev/websites/serro-ai-9596): графитовый фон (`#272727` / `#1d1d1d`), тёплый белый текст, синий акцент (`#3e77e8`) и чёткие прямоугольные элементы управления. Рабочее название — «докчек»; логотип и тексты Serro не используются.

## Запуск в Windows

Из корня репозитория:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Откройте адрес `localhost`, который напечатает Vite в терминале. Не открывайте `index.html` как локальный файл: приложение запускается через сервер Vite. Остановка сервера — `Ctrl+C`.

Сборка и просмотр собранного приложения:

```powershell
npm.cmd run build
npm.cmd run preview
```

Для предварительного просмотра также используйте адрес, напечатанный в терминале.

## Ручная проверка

1. Без файла «Проверить» недоступна; «Пример отчёта» открывается.
2. Выберите файл с длинным кириллическим именем, замените, уберите и выберите тот же файл снова. Проверьте имя и размер. Отмена диалога сохраняет текущий выбор.
3. Перетащите один файл, затем несколько. Во втором случае видно сообщение об ограничении одним документом.
4. Откройте отчёт, выберите каждое замечание и скопируйте текст. Переключите все четыре сценария; частичный результат сообщает о непроверенной области, ошибка позволяет повторить демонстрацию.
5. Проверьте экран на телефоне и пройдите кнопки, ссылки и выбор сценария клавишами `Tab`, `Enter` и `Space`. Убедитесь, что фокус виден и текст не выходит за границы экрана.

Автоматическая проверка сборки: `npm.cmd run build`. Проверка линтером: `npm.cmd run lint`.
