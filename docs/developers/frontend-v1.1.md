# frontend v1.1 — загрузка документа

Раньше «Проверить» открывала демонстрационные замечания. Теперь кнопка отправляет выбранный файл через `POST /api/v1/checks` в единственном поле `file` объекта `FormData`. Ответ `202` показывает «Документ принят, ожидает проверки». Пока запрос идёт, повторная отправка заблокирована. Отказ API объясняется серверным сообщением; при ошибке соединения отправку можно повторить.

«Пример отчёта» остаётся отдельным действием на синтетических данных. Опрос статуса, настоящий отчёт, анализ, авторизация и развёртывание в этот PR не входят.

## Как повторить проверку

В первом терминале:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Запустите локальный backend по его инструкции. Vite ожидает его на `http://127.0.0.1:8000`; другой адрес задаётся в `frontend/.env.local` через `API_PROXY_TARGET`, после чего Vite нужно перезапустить.

Если endpoint ещё недоступен, вместо backend во втором терминале:

```powershell
cd frontend
npm.cmd run mock:api
```

В браузере по адресу Vite:

1. Отправить синтетический `.docx`; в Network проверить `POST`, `FormData.file`, ответ `202`, на экране — подтверждение приёма.
2. При задержанном ответе попробовать нажать повторно: запрос должен остаться один. Для заглушки можно установить `$env:MOCK_DELAY_MS = '2000'` до запуска.
3. Отправить `.txt`, увидеть причину отказа; заменить на `.docx`, отправить повторно и получить `202`.
4. Остановить API, проверить сообщение о соединении и возможность повторить запрос после запуска API.
5. Открыть «Пример отчёта» отдельно — это демо, а не результат отправки.

Сборка и проверки API-клиента: `npm.cmd run build`, `npm.cmd test`. Подробности заглушки и её ограничений — в [frontend/README.md](../../frontend/README.md).

Проверено 14.11.2026: 18 тестов API-клиента и production-сборка прошли. В Chrome проверены реальный POST через прокси Vite на локальную заглушку, `202`, `.txt → 415 → замена на .docx → 202`, блокировка двойного нажатия, повтор после сетевой ошибки, отмена устаревшего запроса при сбросе и отдельное открытие демо. При реально остановленном API проверен `502` прокси, а после запуска — успешный повтор с тем же файлом. Ответы `413`, `422` и некорректный `202` дополнительно проверены подстановкой ответа. На ширинах 320, 390, 768 и 1440 px горизонтального переполнения нет, ошибок JavaScript не обнаружено.
