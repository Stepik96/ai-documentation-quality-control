# Сценарии сервиса проверки документации — scope и версии

Дата: 22.10.2026.

Таблицы из обсуждения пользовательских сценариев. Это рабочие предложения для отбора, а не согласованные требования. V1 — MVP, V2/V3 — развитие; «отдельное решение» — поведение необходимо выбрать до реализации.

## Рабочая основа

| Положение | Статус |
|---|---|
| Сервис предназначен для сотрудников одной компании | Уточнено тобой |
| Проверяем уже подготовленную документацию по проектам внедрения 1С | Уточнено тобой |
| Готового полного Style Guide нет; требования предстоит вывести из примеров | Уточнено тобой |
| Нужны профиль и история с возможностью вернуться к файлам | Обозначено тобой как необходимое |
| MVP: загрузить документ → проверить → получить замечания → исправить самостоятельно | Предлагаемый первый релиз |
| Следующий релиз: дополнительно получить исправленную копию | Предлагаемое развитие |
| Проверка через модель и `SKILL.md` | Техническая гипотеза |
| История хранится именно неделю | Пока пример, срок нужно выбрать |

Правила, выведенные из примеров, сначала нужно согласовать с представителями компании.

## 1. Доступ и профиль

| Сценарий                                        | Предлагаемый этап                           |
| ----------------------------------------------- | ------------------------------------------- |
| Сотрудник получает доступ к сервису             | V1                                          |
| Входит и выходит из аккаунта                    | V1                                          |
| Видит своё имя и рабочую почту                  | V1                                          |
| Возвращается после завершения сеанса            | V1                                          |
| Восстанавливает доступ при использовании пароля | V1, если выбраны пароли                     |
| Администратор предоставляет и блокирует доступ  | V1; без обязательного отдельного интерфейса |
| Меняет отображаемое имя                         | Можно отложить                              |
| Входит через корпоративную учётную запись       | Отдельное решение о способе входа           |
| Самостоятельно регистрируется любой желающий    | Out of scope                                |
| Переключается между разными компаниями          | Out of scope                                |

Для MVP предложена личная история каждого сотрудника. Общий доступ к документам пока не подразумевается.

## 2. Загрузка документа

| Сценарий | Предлагаемый этап |
|---|---|
| Загружает один документ | V1 |

| Загружает неподдерживаемый формат | V1: понятный отказ |
| Загружает слишком большой файл | V1: ограничение и сообщение |

| Загружает сразу несколько документов | V3 |

| Передаёт ссылку на документ вместо файла | Позже |

Форматы нужно выбрать отдельно. Поддержка DOC и PDF требует отдельной оценки.

| Сценарий | Предлагаемый этап |
|---|---|
| Видит количество найденных замечаний | V1 |
| Открывает список замечаний | V1 |

В V1 существуют сохранённый исходник и результат проверки; исправленный файл появляется в V2.

## 6. Повторная проверка

| Сценарий | Предлагаемый этап |
|---|---|
| Исправляет документ вне сервиса и загружает снова | V1 |
| Получает новый самостоятельный результат | V1 |
| Повторяет неудавшийся запуск | V1 |

Для MVP повторная загрузка может считаться новой проверкой. История версий документа — отдельная функция.

## Разделение релизов

| Версия | Ценность для сотрудника | Состав |
|---|---|---|
| V1 — Проверить документ | Понять, что исправить самостоятельно | Доступ, профиль, загрузка, проверка, замечания, личная история, скачивание исходника |
| V2 — Получить исправленную копию | Сократить ручную работу по оформлению | Автоматические правки, отдельная копия, перечень изменений, обработка ошибок формирования |
| V3 — Последовательно доработать документ | Управлять правками и повторными проверками | Версии, сравнение результатов, принятие правок, обратная связь по замечаниям |
| Дальнейшее развитие — Совместная работа | Подключать экспертов и команды | Общий доступ, назначение эксперта, комментарии, согласование |
| Отдельное направление — Интеграции | Проверять документы в привычном рабочем процессе | Корпоративные хранилища, редакторы, другие системы |

Границы релизов предварительные. Для дальнейшего развития учитываем связь: сотрудник → проверка → исходный файл → версия правил → результат → возможные выходные файлы.
