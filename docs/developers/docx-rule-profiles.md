# Кандидаты правил DOCX

Профиль выбирается перед загрузкой. Условия ниже приняты для демонстрации и подлежат согласованию с командой и заказчиком.

| Правило | Профиль и категория | Условие |
| --- | --- | --- |
| R02 | Частное техническое задание · Оформление Word | Текст в ячейках верхнеуровневых таблиц должен быть 10 пт, включая шапки и служебные таблицы. Учитываются явный размер, наследование через стили символов и абзацев и размер по умолчанию. Вложенные таблицы и размеры из сложных стилей таблиц помечаются как непроверенные. |
| R03 | Частное техническое задание · Структура и ссылки | У таблицы с соседней подписью «Таблица N» должна быть текстовая ссылка в отдельном абзаце основного текста. Сама подпись и абзацы оглавления не считаются ссылками. Если подпись отсутствует или для подтверждения ссылки нужно разобрать поля Word, отчёт отмечает проверку как частичную. |
| R01 | Руководство пользователя · Оформление Word | Известное название в основном тексте должно быть целиком полужирным, даже если оно разбито на несколько фрагментов Word. Начальный словарь содержит «Планирование деятельности предприятия». |

Язык и терминология остаются отдельным направлением. Для языковых правил нужны согласованные примеры и критерии оценки.

## Синтетические документы для показа

Из корня репозитория в PowerShell:

```powershell
$samples = Join-Path $env:TEMP 'doccheck-rule-fixtures'
.\.venv\Scripts\python.exe -m backend.tests.rule_fixtures "$samples"
```

Выберите тип документа на странице и отправьте файл из созданной папки.

| Файл | Тип документа | Ожидаемый отчёт |
| --- | --- | --- |
| `tech-spec-ok.docx` | Частное техническое задание | 0 замечаний |
| `tech-spec-findings.docx` | Частное техническое задание | R02 за текст 12 пт и R03 за отсутствие ссылки на таблицу |
| `user-guide-ok.docx` | Руководство пользователя | 0 замечаний |
| `user-guide-findings.docx` | Руководство пользователя | R01 за частично полужирное название объекта |
