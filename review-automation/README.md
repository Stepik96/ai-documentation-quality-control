# Локальное review через Codex: подготовленная версия без merge

Проверено 05.11.2026. Это адаптация PR-Agent для Codex CLI с ChatGPT-авторизацией.
Прямой запуск PR-Agent и полноценный автономный merge НЕ реализованы.
Текущий режим `dry-run`: GitHub не изменяется, отчёты сохраняются локально.
Локальный GitHub-доступ настроен через Windows Git Credential Manager для Stepik96.
Вход в Codex выполняется штатным браузерным процессом; результаты реальных испытаний
и текущий статус см. SETUP-STATUS.md.

## Совместимость и исследование

[Официальная документация Codex](https://learn.chatgpt.com/docs/non-interactive-mode)
описывает запуск `codex exec` из скриптов, JSON Schema и сохранённую авторизацию
аккаунта в автоматизации. Раздел ChatGPT-managed auth допускает нужный аккаунтный
сценарий, но запрещает этот workflow для публичных/open-source репозиториев.
Исследованный репозиторий приватный. Это не безлимитный сервис: действуют лимиты
и доступ конкретного аккаунта. API-ключ, платный API, прокси и извлечение OAuth не используются.
Авторизация проходит только штатным `codex login` на вашем компьютере.
[Авторизация](https://learn.chatgpt.com/docs/auth),
[настройки инструментов](https://learn.chatgpt.com/docs/config-file/config-reference).

Локально: Python 3.12.7, Codex CLI 0.144.6; вход завершён,
`codex login status` => `Logged in using ChatGPT`.
GitHub-плагин имеет доступ к проекту, но его полномочия не доступны отдельному
фоновому Python-процессу. Переноса или извлечения сессии плагина нет.
Первоначальный запуск внутри sandbox не имел доступа к сети/Windows Credential Manager.
В обычном пользовательском окружении чтение приватного репозитория проверено успешно.

В `main` и `develop` кода приложения нет. Открытых PR на момент исследования нет.
В main нет AGENTS.md, .github/workflows, тестов, зависимостей или команд приложения.
В develop есть отдельный черновик `docs/developers/mvp-checks-api.md`;
он не считается утверждённым контрактом основной ветки.
README и текущие сценарии имеют приоритет над историческим пакетом ai-context;
при их взаимном противоречии решение передаётся человеку.
Сами документы пока не являются полным утверждённым ТЗ.

Обе ветки помечены `protected=false`. Запрос rulesets вернул HTTP 403 с причиной:
`Upgrade to GitHub Pro or make this repository public to enable this feature`.
Ничего не покупалось и публичность не менялась. Полная защита ветки не подтверждена.
Неполученный результат API не считается отсутствием всех правил или разрешением обхода.

## Что сделано

- `controller.py`: REST-сборщик контекста, опрос всех открытых PR в main каждые
  180 секунд, пропуск draft, SQLite-состояние, OS-lock, повторная сверка версий,
  максимум две попытки одного контекста, тайм-аут агента 600 секунд.
- `rules.md`: русские правила проекта поверх реального reviewer prompt PR-Agent.
- `result.schema.json`: структурированный контракт с PR, head/base, критериями,
  evidence, замечаниями, предыдущими findings и полнотой покрытия.
- `policy.json`: режим без публикации; пустые списки авторов и идентичности бота;
  обязательный будущий check `review-controller-tests`.
- `tests/`: локальные проверки контроллера и CLI-адаптера с имитацией.
- `.github/`: готовые task/PR templates и workflow без секретов. При установке
  эта папка должна лежать В КОРНЕ РЕПОЗИТОРИЯ; в пакете лежит рядом с контроллером.
- `vendor/pr-agent/`: оригинальные prompt, конфигурация и MIT License.
- `project-snapshot/`, `research.json`: локальные материалы исследования;
  не нужны для запуска, бинарные исходники не копировались.
- `Start-Controller.ps1`: запуск вручную или скрыто в фоне.

Нет отдельного стека для приложения: используется стандартная библиотека Python.
Код PR не checkout-ится и не исполняется. Полные изменённые UTF-8-файлы и diff
читаются через GitHub API; недоступные/бинарные/слишком большие материалы блокируют
положительный итог. Контекст не обрезается молча.
Исторические бинарные образцы DOC/DOCX не анализируются этим контроллером.

## Использование PR-Agent

Точная версия, источники и изменения: [PROVENANCE.md](PROVENANCE.md).
Код PR-Agent не запускается, его модельные адаптеры и GitHub publisher не вызываются.
В prompt каждого анализа реально вставляется фрагмент `pr_review_prompt.system`
из vendored `pr_reviewer_prompts.toml`: от `You are PR-Reviewer` до блока extra_instructions.
Сохраняются focus-on-diff, concrete-trigger, severity, no-style-nits и untrusted-data.
Вместо Jinja/YAML используется контролируемый JSON Schema. Никаких API-эмуляторов.
Ticket compliance и persistent findings адаптированы в свой контроллер и SQLite.

## Решения

`REQUEST_CHANGES`: валидный ответ для текущих head/base содержит доказанное
замечание P0/P1/P2 либо `not_fulfilled` у критерия задачи. В dry-run это только
локальный итог. При разрешённой публикации это формальный GitHub review.
Непонятные требования, недоступный тест и стилистическое предпочтение сами по себе
не являются основанием Request changes.

`APPROVE`: все критерии подтверждены доказательствами, покрытие полное,
нет вопросов/блокеров, риск low, рекомендация no_concerns_found, обязательные CI
успешны, все остальные проверки завершены без ошибок; PR своей команды,
автор разрешён, конфликтов нет, только допустимая документация без чувствительных
путей. Сейчас allowed_authors пуст: реальные PR не получат этот итог автоматически.
`not_applicable` консервативно требует человека: нельзя исключить обязательный критерий решением модели.

`HUMAN`: хотя бы один положительный барьер не выполнен. Изменения поведения
без связанной задачи/критериев, кода, требований, автоматизации, доступов, зависимостей,
развёртывания, исходных материалов и миграций требуют человека. Для произвольных
расширений прав и разрушительных действий нет разрешённой категории merge.

`merge`: ВСЕГДА запрещён в этой версии. Режим `merge` завершится ошибкой до публикации.
REST merge принимает head SHA, но не предоставляет ожидаемый base SHA как атомарное
условие. Двух последовательных GET недостаточно для гарантии от гонки main.
Нужны подтверждённые protection/rulesets, разрешение outstanding threads и
квалифицированный механизм актуализации/merge queue либо эквивалентный барьер.
Требования человека/CODEOWNERS должны исполняться GitHub, обход admin не предусмотрен.

## Безопасность и пределы

Запускайте доверенную установленную копию, а не ветку PR. Не обновляйте контроллер
автоматически из входящего PR. После принятия настройки в main устанавливайте
только проверенную ревизию; инструкции и документы берутся из целевого main.
До принятия настройки это подготовленный локальный пакет, а не правила из main.

Агент работает из пустой временной папки, с read-only sandbox, отключёнными shell,
apps/plugins, браузером, subagents, hooks и image tools; пользовательский config и
exec rules игнорируются. Ему передаётся контекст через stdin, а не GitHub token.
ChatGPT-авторизация остаётся в штатном локальном хранилище Codex. Её файлы не читаются
и не копируются контроллером. Сырые stdout/stderr не сохраняются в отчётах.
Попытка инструмента или ошибка JSONL отклоняет результат. Эти флаги проверены по
справке установленного CLI; фактическая tool isolation с авторизованной моделью
проверена на трёх контролируемых примерах без инструментальных вызовов.
Это не полная проверка всех атак; publication пока нельзя включать без испытаний App.
Sandbox read-only сам по себе не является доказательством полной изоляции чтения.

Модель не получает merge-полномочий. GitHub token остаётся у контроллера;
для dry-run нужны только чтение metadata/contents/issues/PR/checks/statuses.
Для будущего publisher — отдельный GitHub App или технический аккаунт с PR write,
без contents write, administration и merge. Командные логины нужно перечислить явно.
Самоодобрение PR автора GitHub не допускает: свой аккаунт не заменяет отдельного reviewer.
Создание и выдача прав технической идентичности здесь не выполнялись.

Для автоматической настройки отдельного App подготовлен `setup_github_app.py`:
официальный GitHub manifest flow, пользователь вручную подтверждает Create/Install.
PEM сохраняется под Windows DPAPI в `.state/github-app.dpapi`; приложение использует
встроенный `node:crypto` для RS256 и короткоживущий installation token, ограниченный
одним репозиторием. Controller умеет работать через этот App после завершения мастера.
Публикация остаётся dry-run. Исходники не содержат ключей.

Сбой останавливает watch с ненулевым кодом; нет бесконечных ретраев. Повторный запуск
учитывает лимит по контексту. JSON/Markdown сохраняются в .state; там приватные данные
проекта, поэтому не коммитьте и не отправляйте этот каталог. Для новой попытки после
исчерпания лимита изучите last-error; не удаляйте всю базу, теряя защиту от дублей.
Остановка не прерывает текущий subprocess мгновенно: до 600 секунд; перед публикацией
проверяется STOP. Уже отправленный сетевой запрос отозвать невозможно.
Между финальной сверкой и публикацией formal review остаётся сетевое окно;
review привязывается к commit_id, слияние не выполняется.

## Запуск после локальной авторизации

Из каталога `review-automation`:

```powershell
codex login
codex login status
python controller.py doctor
python -m unittest discover -s tests -v
python controller.py once
python controller.py watch
```

В установленной policy используется `github_credential_user=Stepik96`: контроллер
получает GitHub credential через официальный `git credential-manager get`, только
в память процесса, без вывода или записи в проект. Уже сохранённый аккаунт проверен.
В качестве альтернативы перед `once`/`watch` задайте `REVIEW_GITHUB_TOKEN` локально через защищённый механизм
вашего окружения для отдельной идентичности. Не вставляйте значение в чат, скрипт,
историю PowerShell, git или логи. Сессия GitHub-плагина в приложении для этого не подходит.
Environment token не нужен при настроенном Credential Manager. Для первой read-only диагностики можно использовать
локально авторизованный инструмент/credential store, не выводя секреты.

`once` обрабатывает в том числе ранее открытые PR. `watch` продолжает опрос без
сообщений в чат; компьютер и сеть нужны постоянно. После потери питания запустите
watch снова: существующие PR будут обнаружены. Установлен автозапуск Windows
`AI Documentation Review - Read Only`: скрытый pythonw, при входе пользователя,
без автоматического перезапуска после ошибки. Состояние цикла: `.state/health.json`.
Скрытый ручной запуск: `./Start-Controller.ps1 -Background`.

```powershell
python controller.py status
python controller.py stop
python controller.py resume
python controller.py watch
```

Отчёты: `.state/<контекст>.json` и `.md`, сбой: `.state/last-error.json`.
Новых сообщений при неизменном состоянии нет; лог — завершённый review или ошибка.
Для окончательной остановки дождитесь выхода процесса; Ctrl+C — для foreground.
Включённый контроллер сам код не исправляет.

## Испытания и включение

См. [VALIDATION.md](VALIDATION.md). Пройдены тесты с FakeGitHub, фиктивным ответом
модели и mock subprocess; это не доказательство способности модели обнаружить ошибки.
Реальный доступ через GitHub plugin и локальный GCM проверен. Codex авторизован;
результаты настоящей модели на синтетических примерах — в SETUP-STATUS.md.
Реальных PR/комментариев/Approve/Request changes/merge не создавали.

До запроса единственного итогового согласования publication нужно:

1. Выполнить штатный `codex login` локально; дать контроллеру read-only GitHub-доступ.
2. Прогнать настоящий `once` и авторизованный tool-isolation smoke-test.
3. Проверить формальные review и retry после сетевого сбоя в выделенном тестовом репозитории.
4. Указать техническую идентичность и пять точных GitHub-логинов команды;
   принять настройку/CI в main, подтвердить действующие критерии и приоритет документов.
5. Показать результаты и финальную политику пользователю, затем получить одно согласие.

После такого согласия контроллер может использовать `mode=publish` и
`approved_policy_sha256`, полученный командой `python controller.py policy-hash`.
Это техническая блокировка, а не замена человеческому согласованию.
Сейчас hash пуст, режим dry-run. Изменение политики аннулирует hash.
Автономный MERGE потребует дополнительной реализации и испытаний защиты ветки;
он не включается простой сменой настройки. Платные ресурсы не нужны для испытаний
read-only review. Не делайте репозиторий публичным ради снятия ограничений.
